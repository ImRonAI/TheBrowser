# AGENTS.md — Ron Browser Rebuild

Guidance for AI coding agents working in this repository. Assume the reader knows nothing about the project.

## Project overview

**Ron Browser** is a local-first, agentic desktop browser. It combines:

- an **Electron** main process (`electron/`) that owns native browser tabs (`WebContentsView`) and embeds browser automation via the sibling package `electron-playwright-mcp` (a `file:../electron-playwright-mcp` dependency — `npm install` fails without that checkout);
- a **React 19 + TypeScript renderer** (`src/`) that acts as the browser chrome (tab bar, URL bar, agent panel, projects/issues boards, onboarding);
- a **Python FastAPI backend** (`agent/api/`, "Ron Browser API" v4.0.0) built on the **commit-pinned Strands Python SDK** (`deploy/prepare-strands.sh`), which owns all agent sessions, tools, providers, and streaming.

The three processes run separately and communicate over localhost HTTP/SSE. There is also a 24/7 VPS deployment (`deploy/`) where the backend and a headless Electron "cloud browser" run under systemd and the Mac reaches them over an SSH tunnel.

### Ports

| Port | Process | Purpose |
|---|---|---|
| `8765` | FastAPI (`agent/api/main.py`) | Agent Panel chat, sessions, SSE, models, projects, articles |
| `3000` | Electron main | Electron control surface for `electron-playwright-mcp` |
| `8931` | Electron main | Playwright MCP HTTP surface |
| `9222` | Electron main | CDP (Chrome DevTools Protocol) |
| `13000`/`18931`/`19222` | SSH reverse tunnel | The Mac's Electron browser as seen from the VPS (`user` browser target) |

The Vite dev-server port can drift; CORS allows any `localhost`/`127.0.0.1` origin by regex.

## Commands and setup

- Use `venv/`, not `.venv/`; npm scripts and Pyright target it. Python dependencies come from `agent/api/requirements.txt`.
- Before installing Python requirements, run `bash deploy/prepare-strands.sh` from the repo root. It clones GitHub directly into `agent/api/core/harness-sdk` at `563f57d7a387931760a2c3106014cd7c0db4c9bc`; requirements install its full Python package editable. The clone is ignored and reconstructed with `deploy/strands-bidi.patch`. Never copy files from the sibling BidiAgent checkout or prepend its path to `sys.path`.
- `npm install` requires the sibling `../electron-playwright-mcp` package (`file:` dependency).

```bash
npm run electron:dev   # kills stale dev listeners (never the SSH tunnel), then Electron; agents on VPS :8765 when tunneled; optional local Python on 8766 for Live if VPS lacks /bidi
npm run dev:vite       # Electron/renderer only; kills :3000/:8931/:9222 unless RON_DEV_SKIP_PORT_KILL=1
npm run dev:backend    # local API only (port picker); prefer electron:dev so VITE_* matches
npm run build          # dist/electron + dist/renderer
npm run start          # built Electron app
npm run typecheck      # tsc --noEmit
./venv/bin/python -m pytest agent/tests -q
./venv/bin/python -m pytest agent/tests/test_chat.py::test_health
node --experimental-strip-types --test src/lib/panel-stream.test.ts   # renderer tests
shellcheck deploy/*.sh deploy/local/*.sh
```

- Manual Electron launches require `unset ELECTRON_RUN_AS_NODE`; the npm scripts handle this.
- `npm run electron:dev` (`deploy/local/electron-dev.sh`) probes `localhost:8765` and sets **`VITE_API_BASE_URL`**, **`VITE_LIVE_API_BASE_URL`**, and **`VITE_SEARCH_API_URL`** (only when needed). With the SSH tunnel up, **8765 is the VPS** — panel, discover, **search**, projects, memory, and (after deploy) live/teaching all use that origin unless a route is missing and a **8766** sidecar is started. **Do not** pin `VITE_*_URL` in `.env.development.local` (it overrides the script and causes dead-port 404s). Built apps default to `http://localhost:8765`. Guest issue API pinning (`ron-project-api-url-v1`) remains authoritative when set.
- Pyright is not installed in `venv/`; use `npx -y pyright@latest <files>`. `panel_agent.py`, `panel_tools.py`, and `chat.py` carry pre-existing pyright errors — compare error sets against the previous commit rather than requiring zero.
- Fresh venvs must pin `fastmcp[apps]==3.4.0` (the `apps` extra brings `prefab-ui`, which `electron_playwright_mcp.server` imports via `fastmcp.apps.approval`; without it every browser-tool load fails with "unhandled errors in a TaskGroup") and `mcp==1.26.0` **before** `pip install --no-deps -e ../electron-playwright-mcp`: its unbounded `fastmcp>=3.2.0` resolves to fastmcp 4 / mcp 2.2, which violates Strands' `mcp<2.2` pin and removes `fastmcp.tools.tool`. `deploy/vps-install.sh` does this and runs `pip check`.
- Key Python pins: Strands source SHA above with `a2a,mistral,openai,anthropic,gemini,bidi-google` extras, `strands-harness==0.1.2`, `strands-agents-evals==1.4.0`, `strands-xai==0.6.1`, `perplexityai==0.43.5`, `mcp==1.26.0`, `openai==2.50.0`, `anthropic==0.76.0`, `google-genai==2.24.0`, `pydantic==2.12.5`, `huggingface_hub==1.20.1`, `playwright==1.57.0`, `a2a-sdk==0.3.22`.

## Runtime architecture and boundaries

These boundaries are load-bearing; do not casually cross them. `docs/panel-runtime.md` is the pinned authoritative reference.

- **Panel controls**: goal, background tasks, tool execution, context and checkpoint settings are prompt slash commands (`src/lib/panel-commands.ts`), not a header settings form. Commands only configure existing native Strands options before the first message; an existing session's options remain immutable. Checkpoint UI uses the existing AI Elements checkpoint component and resumes via `checkpoint_resume`. The panel agent's **Teach Ron** trigger is in `ChromeToolbar`, beside the panel toggle, so closing the panel does not unmount its teaching studio.

- **Skill teaching** (`agent/api/core/teaching.py`, `core/process_document.py`, `endpoints/teaching.py`, `endpoints/teaching_observe.py`, `src/components/agent-panel/TeachSkill.tsx`): each panel destination and issue agent owns its learned skills. Teach Ron is one native `BidiAgent` (`gemini-3.8-live` by default, see Voice / Gemini Live) seeded with the brief (`title`, `objective`, `context`) and prior journal; the active browser tab (or the window beside the studio, for an internal page) streams at most one JPEG per second through native `RealtimeInput` video. It journals with its **own copy** of the `journal` tool (`core/teaching_journal.py`, same `write/read/list/add_task` semantics as `agent/tools/strands_tools/devops/journal.py`, bound to the lesson workspace, no cwd/env), mirrored into `TeachingService.append_journal` together with auto-journaled user/assistant speech; it must never modify existing tools or skills — `copy_into_lesson` plus `LessonWorkspacePolicy` (native `BeforeToolCallEvent` cancel: editor writes only inside the workspace, `shell`/`environment`/`mcp_client` denied because there is no sandbox) make authoring copy-only. Start captures that browser view, then requests microphone and camera permission; the camera is composited as a small circle at the bottom right of the model's frame. The studio is a full-height side panel the same width as the agent panel. `/finish` prepares an escaped HTML process review only. `/review` requests corrections; `/approve` binds human approval to the exact revision and journal digest before generating `SKILL.md`, `workflow.sop.md`, actual references/scripts and `tool-group.json`. Native SOP source is the pinned `strands-agents/agent-sop` GitHub package: `core/native_sop.py` starts its unmodified MCP server and retrieves the workflow prompt. One native Agent follows the ordered natural-language SOP with the approved tools; this is not a custom deterministic step runner. The teaching studio keeps capture alive when minimized; closing stops it. FastMCP is mounted at `/skills/mcp/` with its lifespan and exposes `get_tool_group` plus skill discovery/read/execution. Generic MCP execution rejects issue scopes; only the authenticated issue agent can bind its own tools. Taught-skill memory is durable even when panel conversations are ephemeral. Issue history returns `owner_id` so guest capabilities never appear in teaching URLs. These trusted-loopback host-execution surfaces must never be added to the ngrok allowlist. See `docs/skill-teaching.md` for contract and verification limits.

- **Session ownership**: `PanelRuntimeManager` owns one live agent per user/session and server-owned invocations. Native `SnapshotSessionManager` pairs with an application run journal. Default storage is ephemeral; `PANEL_STORAGE=huggingface` enables HuggingFace Buckets. Run one writer process. Do not replace SDK execution or snapshot implementations.
- **SSE protocol**: the panel uses versioned, session-sequenced application envelopes (`{version: 1, sequence, session_id, run_id, type, node_path}`), not raw SDK or AI SDK UI streams. Keep `agent/api/core/panel_runtime.py`, `src/lib/panel-stream.ts`, and `src/components/agent-panel/usePanelChat.ts` synchronized. `POST /chat` returns the SSE stream directly; `GET /sessions/{id}` is the canonical snapshot; `GET /sessions/{id}/events?after=<seq>` replays; `/steer` and `/cancel` control runs.
- **Agent composition**: agents are built with `strands.experimental.config_to_agent` (accepts only `name`, `model`, `prompt`, string `tools`) plus constructor overrides for provider instances, managers, plugins, and callbacks. A bare model string selects Bedrock. Providers: Perplexity, Mistral, xAI, Gemini, OpenAI, Anthropic (`PROVIDERS` in `panel_agent.py`). Preserve `stream_async`. Preserve `perplexity_model.py`'s complete function-argument recovery. Server-side tools belong in provider configuration, distinct from `Agent.tools`.
- **Tools**: keep `agent/tools/strands_tools/` off `sys.path` (it shadows the installed `strands_tools` distribution). `tool_catalog` imports library files as `ron_vendored_tools.<category>.<module>` (synthetic package, so relative imports resolve) and publishes them at the `AfterTools` boundary. Core tools (`mcp_client`, `editor`, `shell`, `environment`, `http_request`, `perplexity_search`, `tool_catalog`, `ask_user`) come from installed `strands_tools`/vendored `@tool` modules and run on the host; there is no shell sandbox or Shell MCP.
- **`think` tool** exists only for `provider=perplexity`: the vendored strands_tools `research/think.py`, loaded **unchanged** (`load_vendored_think`, native loader; the SDK injects `agent` and offloads its sync body). Each cycle is a child `Agent` over the parent's model and tools reporting to the parent's `callback_handler` (none in the panel), so think does not stream: it renders as one tool call plus its conclusion. `ThinkToolsGuard` (native `BeforeToolCallEvent`, writable `tool_use`) rewrites the call's `tools` to the parent registry minus `is_parent_only_tool` (think/ask_user/tool_catalog/`strands_*`/browser tools), because think.py inherits every parent tool when `tools` is omitted. `PerplexityResponsesModel` opens a fresh `AsyncOpenAI`/httpx client per request, so think.py reusing `parent.model` on its own event loop is safe (`test_think_tool.py`).
- **Context injection**: browser context (`request_context`) and queued steering go through the SDK's `ContextInjector(render_content, trigger="everyTurn")` plugin, passed in `SessionRun._runtime_options` (the same pattern as strands_harness `Todos`). The SDK appends the text to the last user message of that model call only; it is never written to `agent.messages`, the session or the journal. On a tool-result turn that message holds the `toolResult` blocks, and the pinned Responses (OpenAI/Perplexity) and Mistral formatters serialize the folded text **before** the tool replies; the SDK does not verify that providers accept this, so confirm against the live provider. Steering still queued when an invocation ends becomes the input of a native `AfterInvocationEvent.resume` (a durable user message); a GoalLoop resume is left untouched and the injector delivers steering on its next call.
- **Memory / recall / dreaming** (`core/panel_storage.py`, `core/dreaming.py`, `core/memory_agent.py`, `endpoints/memory.py`): the SDK's own memory wiring (strands_harness `resolve_memory` shape). `get_panel_storage()` is the authority: `PANEL_STORAGE=huggingface` requires `HF_TOKEN`, calls `HfApi.create_bucket(private, exist_ok)` once and never falls back to memory; `main.py` warms it in the lifespan so misconfiguration fails at boot. `HuggingFaceBucketStorage(search_strategy=, cache_bytes=)` implements the native `Storage` Protocol like `InMemoryStorage(search_strategy=)`: `write` indexes through the strategy (default `KeywordSearchStrategy`), `search` delegates to it, and reads are cached by `BucketFile.xet_hash` from the latest `list_bucket_tree` (own writes/deletes invalidate; a foreign writer is seen on the next listing). `create_memory_config(user_id)` returns **two** `SerializedFileMemoryStore`s (native `FileMemoryStore` subclass, per-user process lock) over the user's HF namespace: `panel-memory` (long-term; entries headed `# Topic | Subject` slug-merge into one subject file, newest block last) and `journal` (`entry_files=True`: every `<start_entry>` is **server-stamped** UTC `<created_at>` and filed as `<topic>/<stamp>-<subject>.md`). `MemoryAddToolConfig(stores=["journal"], wait_for_writes=True)` makes `add_memory` write the journal only; `MemoryInjectionConfig(trigger="everyTurn")` injects from both before every model call; the journal store's `get_tools()` publishes the nested-filter `search_memories` (`order/since/until/tags/topic/subject`, over journal + long-term) so the `MemoryManager` registers it beside `search_memory` — never hand-wire it into a catalog. **Dreaming** is the long-term store's native `ExtractionConfig(extractor=DreamExtractor -> ModelExtractor(DREAM_PROMPT), filter=MemoryMessageFilter(exclude=[]))`: the SDK's default `IntervalTrigger(5)` plus `memory_manager.flush()` at session close/shutdown run it on the panel Agent's `aux_model` (`build_model("perplexity", first RON_MEMORY_AGENT_MODELS id)`; unset without a Perplexity key, when the SDK uses the panel model); `exclude=[]` keeps the journal `add_memory` `toolUse` blocks, which `DreamExtractor` renders into the transcript, lists the existing subject headings, and emits tagged (10-12 from `DEFAULT_TAGS`/`RON_MEMORY_TAGS`) `# Topic | Subject` entries; corrections reuse the heading, so the newest line wins. There is no idle tick, timer, `/memory/dream` or `RecallPlugin`. **Recall** is the `recall` tool: strands_harness `make_subagent` with every axis `Fixed` (the model supplies only `task`), a fresh `create_harness` child per call over `resolve_memory(stores, writable=False)` read-only views (the harness's `_ReadOnlyStore`: no `add`, no extraction, no `get_tools`, so `search_memories` is passed explicitly) on a native `ModelRouter(FallbackStrategy)` with `retry_strategy=None`; its events stream as native `ToolStreamEvent`s and render as ChainOfThought (`panel-stream.ts` `CHAIN_TOOLS = {recall, think}`, "Memory/Task/Recalled"). `RON_MEMORY_AGENT=0` drops the tool. Live (`BidiAgent`, no plugins) gets `user_memory_manager(...).tools` with `injection=False` and `extraction=False`. `/memory/entries` is loopback inspection via the stores' `get_tools()`. Tests: `test_panel_storage.py`, `test_dreaming.py`, `test_memory_agent.py`, `test_think_tool.py`, `test_tool_observation.py`.
- **Tool observation (CAT-49)** (`core/tool_observation.py`): the panel Agent sets `trace_attributes={"session.id","user.id"}` (copied by the SDK onto every span) and registers `ToolObservation`, one `AfterToolCallEvent` callback (order 300, after the runtime's 200) that adds a `ron.tool.outcome` span event (`tool_name`, `toolUseId`, `status`, `exception`, `duration`, `retry`) to the enclosing span and flags failures in `agent.state["panel.tool_failures"]`. Tool arguments/results live on the native `execute_tool` spans under `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental`. `RON_TOOL_OBSERVATION=1` wires `strands_evals` `StrandsEvalsTelemetry().setup_in_memory_exporter()` once per process (`strands-agents-evals==1.4.0`). Each outcome also carries **provenance**: `implementation` (registered tool class), `wrapped` (Ron's facade chain via `.wrapped`: `_AsyncNativeTool`/`_RenamedTool`/`_IdempotentMCPTool`) and `source` (`{path relative to PROJECT_TOOLS_DIR, sha256}` from the `__ron_source__` stamp `stamp_source` puts on catalog-loaded tools, else `inspect.getsourcefile` of the innermost callable); `redact_outcome` keeps tool name, arg **keys/types**, exception class/message, status, duration and provenance — argument values and result text never leave the session.
- **Tool repair (CAT-50/51)** (`core/tool_repair.py`, `endpoints/tool_repairs.py`, `agent/sops/repairing-a-broken-tool.sop.md`): **tenant = `user_id`**; a repaired tool is a user-scoped revision under `panel/users/<sha256(user_id)>/tool-repairs/<tool>/{active.json, <rev>/manifest.json, <rev>/files/<source_path>, <rev>/tests/}` (same HF bucket via `_ScopedStorage`); there is no global activation or maintainer promotion. `ToolRepairTrigger` (`AfterToolCallEvent`, order 310, always on unless `RON_TOOL_REPAIR=0`) counts `(tool, exception class)` failures of **every** tool and at `RON_TOOL_REPAIR_THRESHOLD` (2) writes a proposal tagged with `target_kind` (`library` = vendored file, `mcp` = browser/MCP server tool, `core` = installed host tool, `other` = plugin/agent tool). **Every kind is repaired per user**; the kind selects the `repair_kind` the fixer submits: `file` (repaired copy of the vendored module, library only), `adapter` (`/workspace/adapter/<tool>.py` with `transform_input(input)`/`transform_result(result, input)`; `_AdaptedTool` wraps the registered tool — any kind, including MCP/browser tools — through `PanelToolCatalog.replace_tool`/`set_tool_adapter`, so the shared code is never edited), `server` (repaired copy of the `electron_playwright_mcp` package at `/workspace/server/`; on activation `browser_server_env(user_id)` puts it first on **this user's** browser MCP server `PYTHONPATH` via `browser_client_factory(extra_env=<callable>)`, and `PanelToolCatalog.restart_mcp_server` stops/respawns that server in every live session so the repaired package is live at the next invocation; new sessions spawn with it) to `agent.state["panel.tool_repair.request"]`; `SessionRun._announce_repair_proposal` emits `tool_repair_proposed` (durable) after the native stream ends and the renderer shows a Catalyst `Alert` ("Repair / Not now"). Nothing runs without `POST /tools/repairs {user_id, session_id, tool_name}` (loopback-only, session must be idle): `RepairService.start` builds one **fixer** = fresh `create_harness` child (`memory=False`, `session=False`) on `ModelRouter(FallbackStrategy)` over `RON_TOOL_REPAIR_MODELS` (default `openai/gpt-6.1-sol`) at `RON_TOOL_REPAIR_EFFORT` (default `max`, set on the `PerplexityResponsesModel` instance); its **server-side** Perplexity tools are `fixer_hosted_tools()` on the model params (`RON_TOOL_REPAIR_HOSTED_TOOLS`, default `web_search,fetch_url,image_search,sandbox,connector_github,context7`: built-ins by `type`, the managed GitHub connector `{type: connector, id: connector_github}`, Context7's remote MCP `{type: mcp, server_url: CONTEXT7_MCP_URL, authorization: CONTEXT7_API_KEY}` — live-verified on `gpt-6.1-sol`, `mcp_list_tools` returns `resolve-library-id`/`query-docs`); native **A2A** like every Ron agent (`a2a_tools`; `RON_TOOL_REPAIR_A2A_AGENTS` adds fixer-only peers), tools = the harness built-ins `shell`/`read`/`write`/`edit` (`builtin_tools=[...]`, routed through the SDK `Agent(sandbox=)` seam: a per-run `DockerSandbox` — `docker run python:3.12-slim` with `<SESSION_STORAGE_DIR>/repairs/<scope>/<rev>/` writable at `/workspace` and the library, `agent/api/core`, installed `strands_tools` and the MCP server package read-only under `/sources/*`; the SDK's `NotASandboxLocalEnvironment` fallback is reported as sandbox `local` and forces `unverified`), the harness `todos` plugin, read-only `search_memory`/`search_memories`, and application `record_demonstration`/`submit_repair`. The fixer's **input is the native Agent SOP prompt**: `native_sop_prompt(sops, <parameters>, name="repairing-a-broken-tool")` — the pinned `strands_agents_sops` MCP server renders `Run this SOP: <agent-sop name=…><content>…</content><user-input>…</user-input></agent-sop>` with `sop_parameters(...)` (tool_name, target_kind, source_path, base_sha256, sandbox, redacted outcome, failing_request, context_examples, tool_spec, diagnosis) as `user_input`; the SOP follows the package's `agent-sop-format` (Overview/Parameters/Steps with RFC2119 constraints, Examples, Troubleshooting). Input = `strands_evals.diagnose_session` over the exporter spans (`RON_TOOL_OBSERVATION=1`; otherwise the redacted `agent.state` outcome, said so), the exact failing `tool_use` (stays inside the user's own fixer) and `select_context_examples` (≤4 other uses of the tool, most recent first; the fixer synthesizes the rest from the input schema, labelled `synthetic`; side-effecting tools are `dry_run`). SOP order: reproduce → **wrapper audit** (direct vs wrapped call; wrapper-only failure ⇒ `WRAPPER_FIX` on `core/*` ⇒ `needs_maintainer`, never re-wrap) → reflection 1–7 → smallest diff → pytest → five demonstrations in the sandbox → `submit_repair` (`verified` requires failing + 4 context passed; `route_fix(fix_type, source_path, kind)` sends only `SYSTEM_PROMPT_FIX` and a core `WRAPPER_FIX` to `needs_maintainer`; `fixer_sources()` also copy-binds the installed `strands_tools` at `/sources/strands_tools` and `../electron-playwright-mcp/src` at `/sources/mcp` when present). The fixer's child events stream as `ToolStreamEvent`s under the synthetic root tool `repair:<rev>` (renderer `CHAIN_TOOLS` "Repair"); the result is `tool_repair_ready {tool, rev, status, summary, demonstrations, sandbox, route}` (durable) → Catalyst `Alert` + `Table` with **Activate / Discard** (Activate disabled unless `verified`). `POST /tools/repairs/{tool}/activate {user_id, rev}` re-reads the vendored file (`base_sha256` mismatch → 409), writes `active.json`, materializes `files/` under `<SESSION_STORAGE_DIR>/repairs/active/<scope>/<tool>/<rev>/` and calls `PanelToolCatalog.reload_tool` on every live session of that user: `load_library_tool(..., revision_file=)` executes the copy under the vendored module name (`import_vendored_revision`, relative imports resolve) and hands it to native `ToolRegistry.replace` — effective at the SDK's **next** invocation, an in-flight call finishes on the old code; `revision_notice` (`ContextInjector`, userTurn) tells each live session once (`agent.state["panel.tool_repair.notices"]`). New sessions: `catalog.set_revision_resolver(revision_resolver(user_id))` makes `stage_tool` load the active revision for this user before the vendored file (other users unaffected). `/rollback` deletes `active.json` and reloads the vendored file (or unwraps the adapter / drops the server env); restart recovery is `restore_active_markers`/`active.json`. `agent/tests/evals/test_tool_repair_eval.py` (skipped unless `RON_TOOL_REPAIR_EVAL=1`, paid) runs `strands_evals` `Experiment` with `ToolParameterAccuracy`/`ToolSelectionAccuracy` on baseline vs revision and stores `eval.json` beside the manifest. ## Code style and conventions

- **TypeScript**: strict mode; `noUnusedLocals`/`noUnusedParameters` — unused symbols fail `npm run typecheck`. Keep `@/*` and `@catalyst/*` aliases synchronized in `tsconfig.json` and `electron.vite.config.ts`. `src/components/ai-elements/theapp` is excluded from typechecking.
- **Renderer state**: Zustand 5 stores in `src/stores/` (many persisted to localStorage). UI kit: Tailwind 3 + shadcn (`components.json`) + Radix/Headless UI + the Catalyst kit (`@catalyst`).
- **Python**: follow the existing module style in `agent/api/`; env-driven config lives in `agent/api/core/config.py` (loads `.env` from the repo root). Ground Strands work in `agent/docs/strands/` and the installed SDK, not assumptions.
- Make minimal changes; don't refactor adjacent code. Update this file and `docs/` when you change commands, ports, boundaries, or deployment.

## Security considerations

- Secrets (provider API keys, Supabase, AWS) live only in `.env` locally and `/etc/ronbrowser/ron.env` on the VPS; `deploy/ron.env.example` has placeholders. Never sync `.env` (`deploy/sync-to-vps.sh` excludes it).
- `endpoints/articles.py` is SSRF-guarded: public HTTPS only, `MAX_BYTES = 2_000_000`, extracted content prefixed as untrusted.
- Projects API uses Supabase RLS with bearer tokens; guest workspaces use an `x-ron-workspace` 64-hex header hashed (sha256 → uuid5) into an identity, persisted in local SQLite (`guest_projects.py`).
- Electron IPC handlers validate the sender origin (`validateIpcSender`); the renderer window is sandboxed and automation is reachable only via localhost MCP servers.
- Core agent tools (`shell`, `editor`, `http_request`) execute on the host with no sandbox — treat agent output as trusted code execution.
- On the VPS only SSH is public; the API binds `127.0.0.1:8765` and tunnel listeners stay on loopback. Chromium's sandbox stays enabled on the server (setuid chrome-sandbox via the two sudoers rules written by `vps-bootstrap.sh`).

## Deployment

`deploy/` holds the 24/7 VPS layout; see `docs/deploy-vps.md`.

```bash
RON_VPS_HOST=<host> bash deploy/sync-to-vps.sh            # rsync repo + ../electron-playwright-mcp to /opt/ron (never .env)
ssh ron@<host> bash /opt/ron/RonBrowserRebuild/deploy/vps-install.sh   # venv, pins, npm builds, chrome-sandbox bit
RON_VPS_HOST=<host> bash deploy/local/install-tunnel.sh    # launchd SSH tunnel on this Mac
```

- `deploy/vps-bootstrap.sh` — idempotent root bootstrap (Ubuntu; firewall opens only SSH; seeds placeholder env).
- systemd units (`deploy/systemd/`): `ron-api.service` (FastAPI on `127.0.0.1:8765` via `API_HOST`/`API_PORT`) and `ron-browser.service` (headless Electron under `xvfb-run`).
- The Mac tunnel (`deploy/local/tunnel.sh`): `-L 8765` brings the VPS agent API to `localhost:8765`; `-R 13000/18931/19222` exposes this Mac's Electron to the VPS as the `user` browser target. **`npm run electron:dev` expects this tunnel for normal agent work** (HF memory, 24/7 backend). It never kills `ssh` on 8765; it clears stale local Python on 8766 and Electron ports 3000/8931/9222 before starting.
